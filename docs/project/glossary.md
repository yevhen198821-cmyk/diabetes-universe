# Glossary

| Term                                | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Architecture-Driven Development** | Методология разработки Diabetes Universe: архитектурные решения и явные границы предшествуют реализации. См. [ADR-0011](../adr/0011-platform-infrastructure-layer.md) и [01 Project Development Specification](01-project-development-specification.md).                                                                                                                                                                                            |
| **Architecture Approved**           | Статус документа, при котором структура, требования, терминология и решения утверждены; допускается Repository Implementation. См. [02 Project Governance Specification](02-project-governance-specification.md).                                                                                                                                                                                                                                   |
| **Engineering Standards**           | Утверждённые инженерные стандарты репозитория: naming, code, validation, ADR format, Definition of Done. См. [03 Engineering Standards Specification](03-engineering-standards-specification.md).                                                                                                                                                                                                                                                   |
| **Feature Complete**                | Состояние документа или модуля, при котором утверждённый scope реализован в репозитории, навигация и ссылки обновлены, проверки пройдены, merge выполнен, а рабочее дерево чистое. См. [01 Project Development Specification](01-project-development-specification.md).                                                                                                                                                                             |
| **Platform Readiness**              | Состояние, при котором все предусловия, необходимые для корректной работы синхронных методов Runtime, выполнены. Каким способом это состояние достигается (eager preload, selective preload, route-based preload, on-demand preparation и т.д.), определяется выбранной стратегией инициализации, за которую отвечает Composition Root. См. [Platform Readiness](../architecture/localization/platform-readiness.md).                               |
| **Brand Architecture**              | Утверждённая стратегическая архитектура бренда: objectives, immutable decisions, mission, vision, values, positioning, personality, archetypes, communication principles, visual philosophy, scaling rules, and prohibited directions. См. [05 Brand Architecture Specification](../brand/05-brand-architecture-specification.md).                                                                                                                  |
| **Brand Identity**                  | Утверждённая система фирменной идентичности: color and typography strategy, iconography, illustration, photography, motion, tone of voice, writing rules, accessibility, internationalization, asset hierarchy, and usage principles. См. [07 Brand Identity Specification](../brand/07-brand-identity-specification.md).                                                                                                                           |
| **Brand Governance**                | Правила управления брендом: ownership, decision authority, change management, versioning, review and approval processes, asset management, usage compliance, exceptions, deprecation, documentation, and audit requirements. См. [08 Brand Governance Specification](../brand/08-brand-governance-specification.md).                                                                                                                                |
| **Logo Architecture**               | Утверждённая архитектура логотипа: mandatory requirements, evaluation and rejection criteria, approved concept directions, development and evaluation workflows, scalability, digital, animation, and accessibility rules. См. [06 Logo Architecture Specification](../brand/06-logo-architecture-specification.md).                                                                                                                                |
| **Visual Design System**            | Утверждённая архитектура визуальной дизайн-системы: objectives, principles, platform scope, architecture layers, foundation and semantic token categories, component relationships, medical and AI interface rules, accessibility, internationalization, and governance. См. [10 Visual Design System Specification](../design-system/10-visual-design-system-specification.md).                                                                    |
| **Design Tokens**                   | Утверждённая архитектура production design tokens: three-layer hierarchy (foundation, semantic, component), naming principles, token categories, versioning, cross-platform mapping, accessibility, and governance. См. [11 Design Tokens Specification](../design-system/11-design-tokens-specification.md).                                                                                                                                       |
| **UI Component System**             | Утверждённая архитектура reusable UI components: component principles, four-level hierarchy (foundation, primitive, composite, feature-level composition), component categories, states, accessibility, internationalization, cross-platform behavior, and governance. См. [12 UI Component Specification](../design-system/12-ui-component-specification.md).                                                                                      |
| **App Icon Architecture**           | Утверждённая архитектура application icons: philosophy, platform scope, Brand Symbol integration, composition, background, shape, scalability, recognition, accessibility, internationalization, motion compatibility, production principles, validation, and governance. См. [14 App Icon Architecture Specification](../design-system/14-app-icon-architecture-specification.md).                                                                 |
| **Brand Logo System**               | Утверждённая архитектура logo system: Brand Symbol, Primary, Horizontal, Vertical, and Symbol-only logo variants, wordmark architecture, composition rules, clear space, minimum size principles, color architecture, background compatibility, accessibility, internationalization, asset architecture, versioning, and governance. См. [15 Brand Logo System Specification](../design-system/15-brand-logo-system-specification.md).              |
| **Color System**                    | Утверждённая архитектура color system: color philosophy, role hierarchy (Brand, Neutral, Semantic, Surface, Content, Border, Overlay), brand and semantic roles, surface and content architecture, interactive states, theme architecture, accessibility, internationalization, design token integration, evolution, and governance. См. [16 Color System Specification](../design-system/16-color-system-specification.md).                        |
| **Typography System**               | Утверждённая архитектура typography system: typography philosophy, role hierarchy (Display, Heading, Title, Body, Label, Caption, Overline, Supporting Text), numeric typography roles, information hierarchy, reading experience, internationalization, accessibility, theme compatibility, design token integration, evolution, and governance. См. [17 Typography System Specification](../design-system/17-typography-system-specification.md). |
| **Iconography System**              | Утверждённая архитектура iconography system: iconography philosophy, category architecture (Navigation, Actions, Status, Medical, Devices, and related domains), icon roles, recognition principles, information hierarchy, accessibility, internationalization, theme compatibility, design token integration, evolution, and governance. См. [18 Iconography System Specification](../design-system/18-iconography-system-specification.md).      |
| **DU Standard**                     | Высший внутренний стандарт качества Diabetes Universe: DU Principles, review frameworks (design, product, architecture, engineering, AI, accessibility, security, performance), DU Score (100-point scale), certification levels, and review workflow. См. [13 DU Standard Specification](13-du-standard-specification.md).                                                                                                                         |
| **Product Architecture**            | Утверждённая продуктовая архитектура экосистемы: vision, scope, principles, surfaces, modules, responsibilities, user roles, boundaries, scalability rules, and success criteria. См. [04 Product Architecture Specification](04-product-architecture-specification.md).                                                                                                                                                                            |
