# 003. Quick Add

## 1. Цель

Quick Add отображается пользователю как «Добавить событие» — быстрый способ
записать событие дня без перехода на отдельный экран. Первый этап вводит
оболочку выбора типа события и связку с FAB на Timeline.

Компонент отвечает за навигацию к типу события, но не сохраняет данные и не
формирует медицинские рекомендации.

## 2. Первый этап (основа)

### Входит в этап

- открытие панели Quick Add с FAB;
- категории пользовательского ввода в порядке отображения: глюкоза, инсулин,
  питание, лекарство, активность, заметка;
- переход к форме выбранной категории;
- возврат к сетке и закрытие через кнопки панели, backdrop и `Escape`;
- единые акцентные цвета с Event Card System.

### Не входит в этап (этап 1)

- поля ввода и валидация (реализованы в этапах 2–3);
- API, backend и облачная синхронизация;
- категории `reminder` и `ai_insight`: первая относится к планированию, вторая
  не создаётся пользователем вручную.

Примечание: локальная персистентность Timeline через IndexedDB (P4) и контракт
сохранения глюкозы с ожиданием persistence (Wave 3D) реализованы в production;
см. architecture docs.

## 3. Структура

### `QuickAddPanel`

Модальная панель (bottom sheet на mobile, центрированная карточка на desktop).
Два шага:

1. **Выбор типа** — сетка `QuickAddActionButton`.
2. **Экран выбранного типа** — форма выбранной категории.

### `QuickAddActionButton`

Кнопка категории с иконкой, названием и коротким описанием.

### `QuickAddFormLayout`

Переиспользуемый каркас форм Quick Add из `@diabetes-universe/ui`.
Отвечает только за:

- flex-layout формы внутри панели;
- внутреннюю вертикальную прокрутку тела формы;
- запрет горизонтального скролла;
- footer-зону с safe-area padding;
- единые mobile/desktop отступы и поведение на небольших экранах.

Компонент не содержит бизнес-логику категорий: не знает о глюкозе, инсулине,
питании или лекарствах, не управляет состоянием полей, не валидирует значения,
не вызывает haptics и не создаёт Timeline events.

### Поля Quick Add

Переиспользуемые поля из `@diabetes-universe/ui`:

- `QuickAddSelectField` — label, значение/placeholder, optional description,
  открытие внешнего sheet через `onClick`, `aria-haspopup="dialog"`;
- `QuickAddNumberWithUnitField` — связанное поле числа и единицы измерения в
  одном визуальном контейнере, ошибка под общим полем;
- `QuickAddTimeField` — фирменный picker времени с выбором часов и минут,
  кнопками «Отмена»/«Готово», focus trap, `Escape` без сохранения и возвратом
  фокуса на поле;
- `QuickAddTextAreaField` — textarea с maxLength и счётчиком после заданного
  порога;
- `QuickAddFormPreview` — компактный preview записи перед сохранением.

Общие поля являются controlled UI-компонентами: не содержат бизнес-логику
категорий, не создают Timeline events, не вызывают haptics, не обращаются к
Backend/API и не содержат медицинских рекомендаций.

### Контракты

- `QuickAddCategory` и `QuickAddAction` — в `@diabetes-universe/types`;
- конфигурация действий и иконок — в `apps/web/lib/quick-add/actions.ts`.

## 4. Точки входа

- FAB на Timeline (`+`) открывает Quick Add и скрывается, пока панель открыта;
- кнопка «Добавить» в Next Action на Dashboard открывает форму инсулина
  напрямую через `openCategory`;
- Header и FAB на Dashboard открывают сетку категорий.

## 5. Accessibility

- `role="dialog"`, `aria-modal="true"`;
- видимые кнопки закрытия и «Назад»;
- `aria-expanded` на FAB;
- информативные `aria-label` на кнопках категорий;
- закрытие по `Escape`;
- блокировка прокрутки body при открытой панели;
- минимальная область нажатия 44×44 px.

## 6. Второй этап (текущий для глюкозы, инсулина, питания и лекарства)

### Входит в этап

- форма «Глюкоза» с полями: значение, время, контекст измерения;
- контексты: натощак, перед едой, после еды, перед сном, другое;
- единица `ммоль/л` отображается как suffix внутри поля значения;
- время выбирается через фирменный `QuickAddTimeField`;
- контекст выбирается через фирменный bottom sheet;
- форма «Инсулин» с полями: препарат, доза, время, необязательный контекст;
- препараты: NovoRapid, Fiasp, Humalog, Apidra, Lantus, Tresiba, другое;
- доза вводится с suffix `ЕД`, поддерживает целые и десятичные значения;
- контексты инсулина: перед едой, после еды, коррекция, базальный, другое;
- препараты инсулина в bottom sheet сгруппированы: быстрый инсулин, базальный
  инсулин, другое;
- форма «Питание» с полями: способ добавления, тип приёма пищи, углеводы или
  продукты, время, необязательная заметка;
- два MVP-сценария питания: ручной ввод углеводов и расчёт по продуктам;
- тип приёма пищи выбирается через фирменный bottom sheet: завтрак, обед, ужин,
  перекус, другое;
- demo-каталог продуктов локальный и используется только для интерфейса:
  яблоко, банан, овсянка готовая, рис варёный, картофель варёный, хлеб
  цельнозерновой, молоко, йогурт без сахара;
- строка продукта в калькуляторе компактная: выбор продукта, вес порции,
  рассчитанные углеводы и удаление строки без табличной раскладки;
- после выбора продукта под названием отображается значение из demo-каталога:
  `X г углеводов / 100 г`;
- расчёт углеводов продукта выполняется локально по формуле `вес порции ×
углеводы на 100 г / 100`;
- итог калькулятора оформлен отдельным компактным блоком с подписью «Всего
  углеводов» и визуально выделенным числом;
- форма «Лекарство» предназначена для неинсулиновых препаратов; инсулин
  остаётся в отдельном специализированном сценарии;
- препарат выбирается как `MedicationReference` со стабильным `id` и
  отображаемым `name`;
- demo-каталог лекарств локальный: Метформин, Jardiance, Forxiga, Ozempic,
  Mounjaro, другое;
- demo-каталог лекарств содержит только UI-метаданные: форму препарата
  (`таблетки`, `инъекция`) и optional `suggestedUnit`;
- `suggestedUnit` используется только как UI-удобство при пустой единице
  измерения и не является медицинской рекомендацией;
- поля лекарства: препарат, объединённая доза + единица измерения, время,
  необязательный контекст и необязательная заметка;
- контексты лекарства: утром, днём, вечером, перед едой, после еды, натощак,
  другое;
- medication EventCard в compact Timeline отображает дозу с единицей как
  главное значение (`400 мг`, `1 таблетка`, `0,5 мл`), название препарата как
  вторичный текст и контекст при наличии;
- кнопки «Отмена» и «Сохранить»;
- валидация значения в диапазоне 0,1–40 ммоль/л;
- валидация дозы инсулина в demo-диапазоне больше 0 и не более 100 ЕД;
- валидация ручных углеводов в demo-диапазоне больше 0 и не более 500 г;
- валидация веса продукта в demo-диапазоне больше 0 и не более 3000 г;
- валидация дозы лекарства в demo-диапазоне больше 0 и не более 100000;
- соответствие дозы конкретному лекарству не проверяется;
- сохранение в shared Timeline store через semantic creators и IndexedDB
  repository (P4);
- для глюкозы — awaited save integrity contract (Wave 3D): stable event ID,
  dismiss lock during persistence, retry on failure;
- создание `SemanticTimelineEvent` с `occurredAt` (ISO 8601) и `source: manual`
  для реализованных категорий;
- обновление карточки «Последняя глюкоза» после успешного сохранения;
- для активности и заметки реализованы полноценные формы с сохранением в shared
  Timeline store;
- Dashboard Next Action открывает форму инсулина напрямую через `openCategory`;
- медицинские рекомендации и предупреждения о назначениях отсутствуют.

### Форма «Активность»

- поля: вид активности, продолжительность в минутах, время, необязательная
  заметка;
- виды активности: ходьба, бег, велосипед, силовая тренировка, плавание,
  другое;
- валидация: `activityType` обязателен; `durationMinutes` — целое число больше
  0 и не более 1440; `time` обязателен; `note` не более 200 символов;
- после сохранения создаётся `SemanticTimelineEvent` с `kind: activity`, `source:
manual`, `activityType`, `durationSeconds`, optional `note`, `occurredAt`
  через утверждённый temporal utility;
- EventCard показывает продолжительность и вид активности; калории, пульс,
  шаги и медицинская аналитика не добавляются.

### Форма «Заметка»

- поля: необязательный заголовок (до 80 символов), текст заметки (до 500
  символов), время;
- валидация: `text` после trim не пустой; `text` ≤ 500; `title` ≤ 80; `time`
  обязателен;
- после сохранения создаётся `SemanticTimelineEvent` с `kind: note`, `source:
manual`, `title` = заголовок пользователя или «Заметка», `body` = текст заметки,
  `occurredAt` через temporal utility;
- заметка отображается в EventCard, доступна в details/edit/delete, находится
  через поиск по title и text, попадает в фильтр «Заметки».

### Не входит в этап (этапы 2–3)

- API, backend и облачная синхронизация;
- внешняя продуктовая база;
- внешняя база лекарств;
- сканирование штрихкодов;
- напоминания о приёме;
- фото еды;
- AI-анализ.

## 7. Glucose save integrity (Wave 3D — production)

Глюкоза использует отдельный контракт сохранения с ожиданием persistence:

- `prepareGlucoseQuickAddSubmit` валидирует ввод до pending state;
- один stable full event ID на логический submit и все retry;
- `addEventAsync` + IndexedDB commit до success close;
- блокировка dismiss (Escape, backdrop, Back, Cancel, mutable controls) во
  время persistence;
- failure сохраняет введённые значения и освобождает dismiss lock;
- Dashboard и Timeline используют один и тот же save contract.

Остальные категории Quick Add сохраняют через synchronous `addEvent` без
изменений Wave 3D.

## 8. Третий этап (активность, заметка, Next Action)

- формы ввода для активности и заметки;
- связка Next Action → Quick Add с предвыбранной категорией инсулина;
- единый список из шести категорий на Dashboard и Timeline.

## 9. Definition of Done (этап 1)

- панель открывается и закрывается предсказуемо;
- все шесть категорий пользовательского ввода доступны;
- форма выбранной категории отображается после выбора;
- типизация без `any`;
- документация обновлена;
- format, lint, typecheck и build проходят.

## 10. Definition of Done (этап 2 — глюкоза, инсулин, питание и лекарство)

- форма глюкозы открывается после выбора категории;
- форма инсулина открывается после выбора категории;
- форма питания открывается после выбора категории;
- форма лекарства открывается после выбора категории;
- значение, время и контекст сохраняются в shared Timeline store (semantic
  glucose event, mmol/L canonical);
- препарат, доза, время и необязательный контекст инсулина сохраняются в shared
  Timeline store;
- тип приёма пищи, итог углеводов, время, заметка и продукты питания
  сохраняются в shared Timeline store;
- препарат, доза, единица измерения, время, необязательный контекст и заметка
  лекарства сохраняются в shared Timeline store;
- «Последняя глюкоза» обновляется после сохранения;
- типизация без `any`;
- документация обновлена;
- format, lint, typecheck и build проходят.

## 11. Definition of Done (этап 3 — активность, заметка, Next Action)

- форма активности открывается после выбора категории;
- форма заметки открывается после выбора категории;
- активность и заметка сохраняются в shared Timeline store;
- Next Action открывает форму инсулина без промежуточной сетки категорий;
- mobile сетка Quick Add: 2 колонки, 6 карточек, без horizontal scroll;
- типизация без `any`;
- документация обновлена;
- format, lint, typecheck, unit tests, E2E и build проходят.
