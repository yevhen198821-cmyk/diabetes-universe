# Diabetes Universe: готовность к бете, 30 сентября 2026

Оператор по информации владельца: Resulto, Польша. Контакт поддержки:
[resulto.universe@gmail.com](mailto:resulto.universe@gmail.com).

## Что изменено

1. Повтор создания с тем же ключом возвращает первоначальный результат даже после
   изменения или удаления записи. Удалённая запись не появляется снова. Хеш запроса
   теперь учитывает вложенные клинические поля. Старые неполные хеши отклоняются:
   автоматически менять ключ и создавать вторую запись нельзя.
2. Страница `/data` показывает, где находятся данные, выгружает все локальные
   хранилища в JSON и позволяет явно удалить локальную историю текущего профиля.
   Экспорт включает карантин, очередь изменений и сведения о конфликтах. Он не
   является полной выгрузкой аккаунта или готовым форматом импорта/восстановления.
3. Перенос локальных записей подключён к существующему API с возобновлением сессии.
   Учтена версия 2 питания. Перенос требует согласия и сохраняет локальные данные.
4. Добавлены постоянная очередь синхронизации, серверные подтверждения, подписанный
   курсор изменений, доставка удалений и проверка версии при изменении. Потерянный
   ответ повторяется с прежним идентификатором; конфликт сохраняет локальные данные.
   Синхронизация включается пользователем и отдельно разрешается серверным флагом.
5. Успешные чтения событий и страниц синхронизации записываются в аудит перед
   возвратом данных. При отказе записи аудита чтение завершается ошибкой.
   На `/support` размещён реальный контакт; в профиле появились рабочие ссылки.

## Что подтверждено на инфраструктуре

Боевой Vercel-деплой доступен. Без сессии медицинские запросы возвращают 401,
ответы защищены от кеширования. Поддельный тестовый заголовок вход не обходит.
Реальный вход по письму владельца Resend подтверждён: создана сессия, приложение
обратилось к медицинской базе и создало связь аккаунта с субъектом. Полный сценарий
создания, изменения, удаления и проверки изоляции аккаунтов через API ещё не пройден.

В указанном проекте Neon `hidden-wave-09272295` теперь установлены схемы
`medical` и `medical_ops`: 13 миграций выполнены атомарно от `medical_deployer`.
Рабочие роли созданы через SQL с ограниченными правами. Для запросов используется
`du_medical_app`, а старые роли с административными полномочиями не подходят.
Проверки прав и восьми условий каталога прошли на основной базе. Тестовая запись,
изменение, удаление и маркер удаления в синхронизации проверены с полным откатом
тестовой транзакции. Установка сохранила прежние 1 пользователя/9 сессий;
последующий реальный вход создал новую сессию и медицинскую связь.

Vercel уже подключён к новой роли; настроены отдельные секреты подписи и
распределённое ограничение запросов через PostgreSQL. Переменные preview сохранены.
Перенос и синхронизация выключены до проверки соответствующих сценариев. Подробности:
[инструкция и доказательства установки](medical-neon-production-runbook.md).

С разрешения владельца старый снимок авторизации заменён свежим полным снимком
`snap-soft-band-auzhmnc1`. Проверено восстановление в отдельную ветку
`br-frosty-queen-auyiv84q`: сохранены 13 миграций и данные авторизации, прошли
проверки прав и тестовый цикл записи/изменения/удаления с откатом. Боевой сервер
не переключался. На момент снимка клинических записей не было; сохранение
удалённой тестовой записи и маркера синхронизации подтверждено отдельным тестом
копирования медицинской ветки. Переключение приложения после восстановления
и время полного восстановления ещё не проверены. Окно PITR — шесть часов;
автоматическое расписание снимков и мониторинг резервных копий не настроены.

Полная CI-проверка объединённого main прошла: 2145 тестов и 211 браузерных
сценариев, сборка, типы, линтер, форматирование и проверки документации/OpenAPI.

## Почему бета пока не закрыта

Остаются полный авторизованный production-сценарий, проверка двух устройств
и изоляции аккаунтов, полный аудит доступа и отказов,
проверенное удаление аккаунта со всеми связанными данными, обработка удалений
при восстановлении старых резервных копий, мониторинг автоматических резервных
копий, утверждённые юридические документы, интерфейс разрешения конфликтов
и политика хранения очереди/журнала/маркеров удалений.

Для публичного входа нужен подтверждённый домен отправителя в Resend. Текущий
`onboarding@resend.dev` допускает тестовую доставку владельцу Resend; письмо на
адрес поддержки было отклонено. Успешный тест владельца не подтверждает доставку
остальным пользователям.

Контакт поддержки позволяет принять запрос, но сам по себе не выполняет удаление.
Удаление события сейчас сохраняет клинические данные в soft-delete записи.
Очистка браузера не удаляет аккаунт, облако и резервные копии.
Синхронизация работает при открытом приложении; серверный флаг по умолчанию выключен.

Подробные идентификаторы снимков/веток, доказательства и порядок безопасного
развёртывания приведены в
[операционном отчёте](beta-readiness-2026-09-30.md).
